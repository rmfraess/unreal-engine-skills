# Bind a scratch skeletal garment in UE 5.9

1. **Isolate the control.** Duplicate the target skeletal mesh, render input and cloth material. Set clothing usage on the material copy and assign it to the render input before evaluating the graph: evaluation can silently enable the flag on a shared original. Check the dirty-package delta; reload a control package only if it was verified clean beforehand and the flag is its only change.
2. **Build the mask in simulation space.** Start from the skeletal-mesh Chaos Cloth Dataflow template. Import the intended material section; leave separately skinned trim unbound. Read `SimPosition3D` from `SimVertices3D` and write spatial falloffs into `MaxDistance` before `SimulationMaxDistanceConfig`. Zero distance pins the attached regions; give loose regions a gradual transition. Source vertex IDs are not a reliable index into imported particles.
3. **Bind and read back.** Assign the character physics asset, evaluate `ClothAssetTerminal`, then call `CreateClothingAsset` and `AssignClothingToSection` on the scratch target. Verify the intended LOD and section with `GetSectionClothing`; verify `ListClothingAssets` is unchanged on the control.
4. **Verify the live garment.** Isolate the test garment in PIE. For a bound skeletal section, check `GetLiveClothSimulationStats` for dynamic and kinematic particles and the intended body colliders. For a dedicated `ChaosClothComponent`, an empty stats list is inconclusive: read `is_simulation_enabled()` and `is_simulation_suspended()`, then verify deformation using the animated and physical wireframes below and a visible fold that disappears with simulation off and returns with it on. Flags or counts alone do not establish drape.

**Isolate a pose-specific fold before editing assets:**

1. On the actual player, use the same animation, camera, light and other garments for the baseline and candidate. Stop the body animation and use `body.set_position(t, False)` at the failing frame. Leave the world ticking so cloth can settle; repeat at an earlier frame if the onset matters.
2. For each shirt at that same frame, call `cloth.set_enable_simulation(False)`, then `True`, then `False`. Allow the same settling interval and capture the same crop after each switch. Log `body.get_position()` and `cloth.is_simulation_enabled()` with each capture; for the on capture also verify `not cloth.is_simulation_suspended()`. Require the last off capture to reproduce the first before attributing the change to the toggle.
3. Compare across each row first (effect of simulation), then down each column (effect of the garment revision). A point visible with physics off warrants inspecting the posed mesh and weights. A point that appears only with physics on establishes that simulation is necessary in that pose, not that collision or pinning caused it. A milder bulge on the baseline means the revision amplified a shared response; it does not prove the revision introduced a new solver fault.

**If the fold requires simulation, isolate the assigned body collider:**

1. Duplicate only the cloth asset. In its owned Dataflow graph, verify `SetPhysicsAsset.PhysicsAsset` has no incoming link before setting `{'PhysicsAsset':'None'}` with `set_node_properties`; a connected input overrides the local value. Evaluate `ClothAssetTerminal`, save only the duplicate, then read back the empty assignment, the original collider on the control, and identical SIM/RENDER mesh inputs. Leave the character’s shared physics asset intact.
2. At the held failing frame, use `cloth.set_cloth_asset(...)` to swap original → no-collider copy → original. Keep simulation enabled and unsuspended. Give each state the same settling time, verify the animation position, and capture both dressed and unmasked views from the same camera.
3. At the visible defect, [compare body and cloth depth](cloth-fit-depth.md) on the same valid pixels across all three captures. Verify body depth stayed fixed and check for negative gaps as well as the median: a positive median alone can hide local clipping. Report unrelated skin breakthroughs separately.
4. If the fold disappears and returns with the collider while the patch stays outside the skin, attribute the response to the assigned collider **in that pose**, not to a particular primitive. Use `PhysicsToolsets.PhysicsAssetToolset.GetBodyNames` and `GetBodyShapes` to shortlist nearby shapes; isolate one before changing it. If the fold persists without the assigned collider, inspect the transition between pinned and free cloth. A collider-free garment is a diagnostic, not a shipping fix.
5. For a capsule, project its posed axis and caps into the failing view; identify the bone **and shape index**, since one bone can own several capsules. Test one shape on a garment-only physics-asset copy. If only one end pushes cloth outward, keep the radius and opposite end fixed: shorten the cylinder by `d` and move its center `d/2` along the axis toward the retained end. Read back both bone-local endpoints and the unchanged neighboring shapes. Recheck unmasked support at both ends through lift and release; a smoother held fold can still bunch in motion.

**Isolate a render spike:** Hold the failing pose in PIE. Capture `p.ChaosCloth.DebugDrawAnimMeshWired` and `p.ChaosCloth.DebugDrawPhysMeshWired` separately with `p.Chaos.DebugDraw.Enabled` on. A partial wireframe can be the `p.Chaos.DebugDraw.MaxLines` cap: raise it for the capture and confirm coverage of both sleeves. Compare colored wires, not the black depth silhouette, with the visible render surface; restore all original CVar values and stop PIE.

**Check the joined shirt, not just the sleeve.** An isolated sleeve can pass the reach while the complete garment stretches at the armholes. Compare the rendered pose with simulation disabled first. For a weight-transfer defect, keep the solver and mesh fixed: blend weights continuously across the stitched armhole by surface distance (including across split UV vertices), and retain local body weights on the shoulder tops and neckline. Compare the accepted shirt and candidate at idle, elbow bend and full reach, front and back, with the same pose, light and camera. Inspect the collarbones as well as the underarm: reject a smoother reach if it introduces a standing crease or exposes skin. If using adjacent-face angles, compare the same seam edges across poses; a lower peak-pose percentile does not clear a visible regression.

**When regular bands remain with simulation off:** compare the same pose in plain gray and with cast shadows disabled. If the bands survive, count geometric positions versus UV-split vertices within each panel. Test a continuous geometric mesh with separate per-corner UV elements and shared normals, preserving weights, material, cut and solver; compare the live render before sculpting folds or stiffening cloth. Only merge points confirmed to belong to the same sewn surface, never stacked layers.

**When a tuck stays flat, test attachment before recutting:**

1. Hold the pose and camera; capture the waistband from behind with simulation off, then on. Inspect `SimulationMaxDistanceConfig` and its input map in the strip *above* the band. Report zero-distance samples over total samples in that strip. Label a falloff sampled on source vertices as an estimate, not a runtime particle count.
2. If the strip is pinned, duplicate only the cloth asset for this mask-only test. Keep the trousers fixed; verify `SkeletalMesh_SIM` and `SkeletalMesh_RENDER` still reference the control mesh. Change only the strip's `MaxDistance` and assert the map below the band is unchanged, so the tuck has the same anchor.
3. Compare idle, stride, reach and return at the same camera distance. Look at the lower edge: does fabric turn over the band at rest and draw out under tension? Reject isolated dimples above a still-straight edge even if more points move. That rules out the tested mask, not every attachment; trial extra panel length separately rather than calling it a proven fix.

**When tuning apparent weight:** Read the *evaluated garment’s* mass mode, density, `MinPerParticleMass`, bending, damping and collision thickness before adjusting them. In density mode, compare density × simulated area (m²) with the mass floor × particle count for the particles being considered: if the floor dominates, the density alone cannot describe the mass. Treat that calculation as a diagnostic bound, not measured runtime mass. Use the [Blender cloth manual](https://docs.blender.org/manual/en/latest/physics/cloth/settings/physical_properties.html) to distinguish mass, bending and damping, and [Epic’s cloth dynamics tutorial, fabric comparison at 8:51](https://www.youtube.com/watch?v=wq0lY7vhF5w&t=531s) to choose a Chaos test; neither supplies a universal linen preset.

**Motion reference:** [4D-DRESS real-clothing capture](https://files.ait.ethz.ch/projects/4d-dress/data-format.gif) shows the clothed performer alongside derived representations. Use the captured garment for visible continuity and fold location; use a clip with a visible stop to judge settling time.
